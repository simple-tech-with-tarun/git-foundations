# Git Branching Strategies

## Overview

Git branching strategies define how teams organize branches and integrate changes during software development.

Different strategies support different development workflows, release processes, and collaboration models.

This chapter introduces three commonly used branching strategies:

- **GitHub Flow:** A lightweight workflow based on short-lived feature branches and pull requests.
- **Git Flow:** A structured workflow using dedicated branches for development, releases, and production fixes.
- **Trunk-Based Development:** A workflow that emphasizes frequent integration into a shared main branch.

The exercises use practical Git workflows to demonstrate how these strategies operate and when each approach may be appropriate.

## Learning Objectives

By completing this chapter, you will learn how to:

- Understand the purpose of Git branching strategies.
- Explain the GitHub Flow workflow.
- Understand the role of branches in Git Flow.
- Explain the principles of Trunk-Based Development.
- Compare the advantages and trade-offs of different strategies.
- Select an appropriate branching strategy based on project requirements.

## Prerequisites

You should be familiar with:

- Creating and switching branches.
- Making commits and inspecting commit history.
- Merging branches.
- Creating and reviewing pull requests.
- Basic commands such as `git status`, `git branch`, `git switch`, and `git merge`.

Understanding their differences helps teams choose an approach that fits their collaboration model, release frequency, and project requirements.
